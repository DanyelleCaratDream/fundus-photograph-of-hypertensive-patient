# T1-256 设计稿：从 T1 权重做 256 微调（2026-11-13）

> 上游：T1（A_clean 初始化，128px，20,010 步）已通过人工五维；
> 推理侧探索（DL-EX-028）证明 raw/EMA × 50/100 NFE **无可辨识差异**，采样不是瓶颈。
> 本实验回答：**把分辨率从 128 提到 256，能否改善血管细节、视盘结构与边界形状？**

## 1. 目标与非目标

**目标**：在 61 张 HR severe 上，从 T1 的 raw 权重出发，改在 256px 训练，
产出比 T1@128 更清晰的血管、更稳定的视盘结构、更圆的边界。

**非目标**：
- 不重做 A_clean 的 256 预训练（成本高一个数量级）；只验证「128 先验 + 256 微调」能否成立。
- 不改网络结构、不加新损失；本实验只变分辨率。
- 不替换 T1 的预注册主结果（T1@128 仍是主结果，本实验为后续分支）。

## 2. 设置（预注册）

| 项目 | 设置 |
|---|---|
| 初始化 | T1 `results/cfm128_hrsevere_t1_ac/models/final_model.pth` 的 **raw** 权重（`--init_weights_only`） |
| 数据 | `fundus/hrsevere_61_sq256`（61 张）；条件 `CFM/data/conditions_hrsevere_61_256` |
| 分辨率 / 架构 | 256px，base_dim 128 |
| Micro-batch | 1（8GB 显存约束） |
| 梯度累积 | **2**（`--accum_steps 2`），有效 batch = 2 |
| 轮数 / 更新 | **667 轮 × 30 次更新 = 20,010 次**（每轮 61 张：60 张参与、1 张不进该轮） |
| 数据曝光 | 667 × 60 = **40,020 张**（与 T1 的 667×30×2 = 40,020 完全一致） |
| 损失 / seed | L1 + LPIPS 0.1 + color 0.01；seed 42（与 T0/T1 同） |
| 评价权重 | raw；每 50 轮存档；**不允许中途挑最佳 checkpoint** |
| 验收 | `verify_training.py --expect-epochs 667 --steps-per-epoch 30`；raw strict 加载 0/0；日志完整 |

**B\* 的取舍（老师 2026-11-14 拍板）**：同时对齐三件事——数据曝光（40,020）、
优化器更新（20,010）、有效 batch（2）。每轮 61 张中固定 60 张参与、1 张不参与该轮
（shuffle 每轮重洗，被丢的样本逐轮轮换）。这比单纯「667 轮 × batch1」更干净：
后者曝光数相同但更新次数翻倍（40,687）。

**梯度累积实现核查（2026-11-14）**：`train.py` 原代码无累积，已新增 `--accum_steps`
（loss 按 1/accum 缩放；仅在累积满时 step / zero_grad / EMA / global_step；epoch 末尾丢弃不完整组）。
5 张图冒烟测试：batch1 × accum2 → 每轮 2 次更新、残余 1 张被丢弃、global_step=4、ckpt 记录 accum_steps。
默认 `accum_steps=1` 时行为与旧代码完全一致。

**成本预估**：参考 `cfm256` 历史日志，256px/batch1 约 **105–167 s/轮**；
667 轮约 **19–31 小时**（含热降频）。这是本实验最大的代价。

### 2.1 开训前核查（2026-11-14，全部通过）

1. **权重 strict 加载**：把 T1 raw 权重载入 256 配置 UNet（86.9M 参数），
   `load_state_dict(..., strict=True)` **通过**（无 missing / unexpected）。架构与分辨率无关，128→256 兼容。
2. **128 / 256 图像严格对应**：61 个 stem 完全一致；61/61 张 `sq128` 与 `sq256` 的 Lanczos 下采样
   **逐像素完全一致（MAE = 0）**。`sq256` 为 58 张 jpg + 3 张 png，`sq128` 全部 png；
   由于 128 版由同一解码像素派生，内容无差异；仅 256 版保留了高清 JPEG 压缩噪声（披露项，非变量）。
3. **条件图与图像配对**：61/61 张 mask 用 `prep_conditions.extract_vessel_mask` 从对应图像重推导，
   与存档**逐字节一致**。注意：128/256 的 mask 是**各自分辨率下重新提取**，不是放大同一张——
   跨分辨率 IoU 均值 0.66（各膨胀 1px 后 0.82），最优平移 (0,0) 占 58/61；
   差异来自固定尺寸形态学核的相对尺度，不是错位。此项作为「除分辨率外唯一的数据侧差异」如实披露。
4. **损失一致**：两个 preset 共用同一 `COMMON`：
   `--loss_type l1 --use_lpips --lpips_weight 0.1 --color_weight 0.01`；
   `cfm256_t1_ac` 只改数据/分辨率/batch/轮数/output，不加任何加权损失。
5. **预算口径（已冻结为 B\*）**：667 轮 × 30 次更新 = 20,010 次更新，
   数据曝光 667 × 60 = 40,020 张；有效 batch = 1 × 2（梯度累积）= 2。
   三项同时与 T1 对齐。每轮 61 张中固定 1 张不参与（shuffle 轮换）。
6. **学习率与调度（冻结）**：Adam，lr = 1e-4，**无学习率调度**（与 T1 完全一致）；
   不引入 warmup / cosine，避免把预算之外的变量带进来。
7. **EMA（冻结）**：decay = 0.9999，按**优化器更新**更新（不是按 micro-batch），
   随 checkpoint 保存；**主结果用 raw 权重**，EMA 仅在需要时作辅助对照。
8. **mask 披露（冻结）**：256px 条件图是**重新提取**而非 128px 放大，线宽/边缘存在系统差异
   （跨分辨率 IoU 0.66，膨胀后 0.82，对齐 (0,0)）。本实验比较的是
   「分辨率提升 + 对应条件重提取」的整体效果，**不能把改善完全归因于分辨率**；论文与报告按此表述。

## 3. 生成与对比口径

- 生成：4 seed（42/1042/2042/3042）× 8 固定条件 = 32 张，256px，raw，Euler 50 NFE，
  条件用 `conditions_hrsevere_61_256`（排序前 8 张，与 128 版同序）。
- **主裁决 = 作者五维人工判断**（整体外观 / 血管细节 / 视盘结构 / 伪影 / 多样性）。
  展示方式：T1@128 用 Lanczos 放大到 256，与 T1-256 原生 256 并排，保证同屏可比。
- **盲评规则（2026-11-14 增补，防挑图）**：
  1. 每个 seed 的两行**随机标为 A / B**（随机种子固定并记录），A/B 对应关系写入独立 JSON，
     评分完成前不打开；
  2. **4 个 seed、8 个固定条件全部展示**，不允许只挑好看的图，也不允许删 seed；
  3. 每 seed 按五维打 1–5 分并给出偏好（A / B / 平手），再汇总；
  4. 报告逐 seed 结果与**最差 seed**，不只报均值；
  5. 评分完成后一次性揭盲；若条件允许，请第二人（老师）对其中 1–2 个 seed 独立盲评。
- **客观指标（分两层，禁止跨分辨率直接横比）**：
  1. **原生分辨率**：两臂各算 `pilot_metrics.py` 三项，只用于各自 seed 间一致性，**不做 128 vs 256 比较**；
  2. **共同网格**：把两臂都缩放到 256（T1 放大）和 128（T1-256 缩小）各算一遍，
     明确标注「缩放会改变梯度能量，只作描述，不单独裁决」。
  3. 若两层仍无法给出稳定结论 → 升级到六维评分（`eval_scripts/score_scheme.py`），
     但需先把两臂产物整理成 eval_data JSON 口径，届时另写设计。

## 4. 判定标准

- **成功**：作者五维中「血管细节 / 视盘结构 / 边界」至少两项 **稳定优于** T1@128，且整体外观不劣化。
- **部分成功**：仅一项改善 → 记录，再决定是否叠加血管加权（B 路线）。
- **失败**：无明显改善或整体外观劣化 → 判定 61 张数据 / 条件设计是瓶颈，转 B/D 或补数据，
  不再在分辨率上投入。
- 所有结果无论成败都登记 `EXPERIMENTS.md`（新建 DL-EX-029）。

## 5. 已考虑但未选的路线

| 路线 | 为什么不选（本阶段） |
|---|---|
| B. 血管加权微调 @128 | 只提血管对比度，128px 细节上限仍在；等本实验失败再上 |
| D. 加视盘条件 | 视盘检测在 severe DR 上不可靠，条件错了会反噬；研究成本最高 |
| 重做 A_clean@256 预训练 | 成本高一个数量级；先验证「128 先验 + 256 微调」是否够用 |

## 6. 已确认（2026-11-14，老师回复）

- **预算口径：B\***——667 轮、batch1、梯度累积 2、有效 batch 2、20,010 次更新、40,020 张曝光。
- **盲评规则：认可**；老师要求保留 6 条（全 seed 全条件、A/B 随机、评分前不揭盲、五维 1–5、
  逐 seed + 均值 + 最差 seed、不删结果），并**尽量请老师做第二位独立评分者**。
- **mask 披露：接受**——按「分辨率 + 条件重提取整体效果」表述，不单独归因分辨率。
- 学习率/调度与 EMA：已冻结（§2.1 第 6、7 条）。
- 剩余： 「共同网格」客观指标按 §3 执行，作为辅助。
