# 审核流程

## 1. 提交

- 组员把交付物放在 `submissions/A/` 或 `submissions/B/`。
- 每份交付首页用 `提交模板.md`，写明输入文件 sha256、环境、运行命令。
- 不要把结果直接改到任何主文档（`EXPERIMENTS.md`、`PROJECT_STATE.md`、报告正文）。

## 2. 组长审核（逐项）

1. **输入未变**：按 `sha256清单.txt` 核对，输入文件不得被修改。
2. **可重复**：在干净环境按提交命令重跑，结果一致（点估计应完全一致；
   bootstrap 若 seed 与实现相同应一致，否则解释差异）。
3. **数字可追溯**：每个数字能追到输入文件 + 代码位置。
4. **表述边界**：没有"患者级独立""统计显著""消除随机性"等越界表述。
5. **对照验收清单**逐条打勾。

## 3. 结论

| 结论 | 含义 | 后续 |
|---|---|---|
| 通过 | 全部满足 | 并入正式记录（由组长操作） |
| 有条件通过 | 主要结果可用，缺摘要/模板/图注等 | 限期补齐后转通过 |
| 退回 | 数字对不上、无法复现、越界表述 | 写明最低补做项，重新提交 |

## 4. 记录

- 状态记入 `审核台账.csv`。
- 退回必须写"最低补做项"，不接受笼统的"再改改"。

## 5. 两条特别注意

- **不一致不是错误**：复算与现有数字不同，先定位原因（实现差异/数字错误），
  不得直接覆盖原结果，也不得为了"对上"改自己的实现。
- **组员互审不互替**：A 的报告可由 B 检查指标定义与呈现；B 的审计可由 A 检查证据链。
  最终裁决由组长做。
