# 结论卡（每份交付的强制格式）

> 导师 2026-11-17 定的共同提交标准：**每条结论必须同时给出五要素**。
> 报告里出现但结论卡上没有的结论，一律视为未提交。

## 五要素

| 要素 | 要求 |
|---|---|
| 1. 结论 | 一句话，可证伪；不写"效果较好"这类空话 |
| 2. 证据文件 | 具体文件路径 + 字段/行号；能在包内直接打开 |
| 3. 计算方法 | 统计量/公式、参数（B、seed、分箱、权重方式） |
| 4. 可复现脚本 | 脚本路径 + 入口命令 + 输入 |
| 5. 局限性 | 这个结论**不能**推出什么；样本量/覆盖范围/已知偏差 |

## 模板

```markdown
### C-<编号> <一句话结论>

- 证据文件：`<路径>`（字段：`<...>`；行号：`<...>`）
- 计算方法：<公式/统计量>；参数：<B, seed, 分层方式>
- 可复现脚本：`<脚本路径>`；命令：`<...>`
- 局限性：<不能推出什么；样本量与覆盖范围>
```

## 示例（只示范格式，不是结果）

### C-01 A1 与 A0 的 QWK 差值在重跑预测上未观察到方向稳定的差异

- 证据文件：`00_common/predictions/A{0,1}_seed*.json`（字段 `y_true`、`logits`）
- 计算方法：逐 seed QWK 差 + 配对分层 bootstrap，B=1000，seed=20261117
- 可复现脚本：`submissions/A/recompute.py --task A1`
- 局限性：test 仅 71 张；CI 为图像级重采样，不能外推到患者；只覆盖 11-15 重跑

## 交付格式

- 报告正文按结论编号组织；
- 另交 `submissions/<A|B>/结论卡.csv`，列：
  `编号,结论,证据文件,计算方法,可复现脚本,局限性,对应报告章节`
- 结论卡与报告必须一一对应；组长按卡验收。
