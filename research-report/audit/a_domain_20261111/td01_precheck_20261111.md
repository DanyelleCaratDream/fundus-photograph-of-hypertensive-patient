## 二、核对中发现的两个设计问题（会影响 T1 的有效性）

### 问题 A：旧 A 域权重是用「增强错位」管线训练的

2026-07-28 版 `train.py` 存在 11-06 才修复的两个缺陷：

1. `cond_transform` 构造后**未传入** `FundusDataset`（只传了 `transform=transform`），数据集回落到 `cond_transform or transform`；
2. `transform` 与 `cond_transform` 各自独立调用 `RandomHorizontalFlip(p=0.5)` + `RandomRotation(15°)`，
   两次调用随机参数**互不相关** → 图像与血管 mask 在约一半样本上**方向不一致**。

**含义**：旧 A 域权重是在"条件图与图像约 50% 错位"的数据上学的，条件分支的可靠性存疑。
直接拿它当 T1 初始化，等于把该缺陷带进正式实验；若两阶段都用同一错位权重，则 T0/T1 对比本身仍"干净"（差异只来自初始化），但**论文需披露预训练阶段缺陷**。

### 问题 B：A 域是 DDPM（噪声预测），T0 是 CFM（速度场）——目标函数不一致

- 旧 A 域：`loss = F.l1_loss(predicted_noise, noise)`，1000 步 DDPM
- T0（20,010 步试点）：CFM，预测速度 `v = x1 - x0`，Euler 采样
- 项目此前记录（EXPERIMENTS 执行记录 20）已发现 **DDPM→CFM 存在时间轴反转**，为此加过 `--cfm_time_align` 开关

**含义**：T1 = "A 域权重初始化 + CFM 目标域训练"属于**跨目标函数初始化**。可行（架构相同，历史 cfm128 就是这么做的），
但需要二选一并在论文写清：① T1 打开 `--cfm_time_align`；② 或用 CFM 目标重训 A 域（额外约 10–15h）。

## 四、T1 开跑前必须处理的一个技术陷阱

`train.py:1154` 用 `start_epoch = checkpoint["epoch"] + 1` 决定起点；A 域 checkpoint 的 `epoch = 779`。
若直接 `--epochs 667`，`range(780, 667)` 为空 → **训练循环一次都不跑，直接"完成"**。

处理方式（二选一）：
- 复制一份 checkpoint 并把 `epoch` 改写为 −1（语义：目标域训练从 0 计）；
- 或直接用 `--epochs 1447`（=779 + 667 + 1），让总轮数对齐但日志 epoch 号含预训练偏移（不推荐，易误读）。
