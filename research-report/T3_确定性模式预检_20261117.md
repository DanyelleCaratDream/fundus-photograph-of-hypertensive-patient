### 2.1 `classify_project/scripts/train_classifier.py`

新增两个函数（放在模块常量之后）：

```python
def enable_determinism() -> None:
    """DL-EX-032：打开**严格**确定性（warn_only=False，不支持即报错）。

    `CUBLAS_WORKSPACE_CONFIG` 必须在 CUDA 初始化前生效。正式训练由
    `run_t3_pilot.sh` 在启动 Python 前 export；这里的 setdefault 只在
    "本进程尚未触碰 CUDA" 时有效，是兜底而**不是**主要手段。
    """
    os.environ.setdefault("CUBLAS_WORKSPACE_CONFIG", ":4096:8")
    torch.use_deterministic_algorithms(True)      # warn_only=False
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False


def determinism_state() -> dict:
    """当前确定性/版本/硬件快照，写入每次训练 JSON。只读，不改任何状态。"""
    cuda_init = bool(torch.cuda.is_initialized())   # 先取，get_device_name 会触发初始化
    return {
        "deterministic_algorithms": bool(torch.are_deterministic_algorithms_enabled()),
        "cudnn_deterministic": bool(torch.backends.cudnn.deterministic),
        "cudnn_benchmark": bool(torch.backends.cudnn.benchmark),
        "cublas_workspace_config": os.environ.get("CUBLAS_WORKSPACE_CONFIG"),
        "torch_version": torch.__version__,
        "cuda_version": torch.version.cuda,
        "cudnn_version": torch.backends.cudnn.version(),
        "gpu_name": torch.cuda.get_device_name(0) if torch.cuda.is_available() else None,
        "device": "cuda" if torch.cuda.is_available() else "cpu",
        "cuda_initialized": cuda_init,
    }
```

`main()` 的顺序（关键在于**在任何 CUDA 调用之前**完成环境变量与开关）：

```python
def main() -> int:
    args = build_argparser().parse_args()

    # 必须在任何 CUDA 调用之前：环境变量 → 确定性开关 → 快照
    cuda_was_init = bool(torch.cuda.is_initialized())   # is_initialized 不触发初始化
    if args.deterministic:
        enable_determinism()
    det_state = determinism_state()
    det_state["cuda_initialized_before_enable"] = cuda_was_init
    run_meta = {"deterministic_flag": bool(args.deterministic), "determinism": det_state}
```

### 2.2 `classify_project/scripts/run_t3_pilot.sh`（最终版全文）

```bash
#!/usr/bin/env bash
# DL-EX-032：T3 合成 HR-severe 图像分类增强 pilot（9 次训练）
set -u
cd "$(dirname "$0")/../.."

# 必须在启动 Python（CUDA 初始化）之前生效，供确定性模式的 cuBLAS 使用
export CUBLAS_WORKSPACE_CONFIG=:4096:8

DATA=fundus/HRSG_4_758_sq256
OUT=classify_project/results/t3_pilot
CW="1.15,0.985714,0.985714,0.907895"     # 冻结：由 A0 真实训练集 552 张算出
SEEDS="42 52 62"
DETERMINISTIC="--deterministic"          # DL-EX-032 三组统一
mkdir -p "$OUT"

run() {
  local tag="$1"; shift
  echo "########## ${tag} ##########"
  python -X utf8 classify_project/scripts/train_classifier.py \
    --data "$DATA" --size 256 --seeds $SEEDS --epochs 30 \
    --batch-size 16 --lr 1e-4 --num-workers 0 --quiet \
    --class-weights "$CW" --arm-label "$tag" $DETERMINISTIC \
    --out "$OUT/${tag}_20261117.json" "$@"
}

want="${1:-ALL}"
case "$want" in
  ALL|A0) run A0 ;;
esac
case "$want" in
  ALL|A1) run A1 --extra-train-severe-dir fundus/t3_synth_128 --fixed-draws 552 ;;
esac
case "$want" in
  ALL|A2) run A2 --extra-train-severe-dir fundus/t3_synth_256 --fixed-draws 552 ;;
esac

echo "########## 完成 ##########"
```

## 六、报告表述修正（已按导师定稿改）

`T3_随机性排查_20261117.md` 中"同 seed 的 A0/A1/A2 真正配对，ΔQWK 的噪声下限降到 0"
已替换为：

> 确定性模式减少了同一训练配置、同一随机种子及相同运行环境下由非确定性计算引入的
> 重复运行差异，使同 seed 结果具有更好的计算可复现性。但 A0、A1、A2 的数据池与抽样
> 机制并不相同，因此三组之间仍然存在训练数据组成、样本曝光及优化轨迹差异。确定性
> 设置不能消除这些实验变异，也不能消除不同训练 seed 之间的差异。

并补注：

- A0 每轮遍历完整真实训练集 552 张；A1/A2 每轮从 584 张池抽 552 张
  → 三组同 seed 是**种子层面的配对设计**，不是逐 batch 一一配对的严格控制实验；
- `0.02` 只作"实际意义参考幅度"，**不得**把"超过 0.02 且三个 seed 同向"
  解释成统计显著或已排除所有噪声。
